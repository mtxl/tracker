# Раздатка студента

## Занятие: агенты в OpenCode для аналитика

**Что нужно:** ноутбук, проект `tracker`, Python 3.8+, OpenCode 2.x.
**Как работаем:** в парах, роли «драйвер» и «навигатор», меняемся каждые 8–10 минут.

## Что такое OpenCode

OpenCode — это агентская среда. Вы ставите задачу, а агент сам читает файлы,
предлагает план, вносит изменения и запускает команды. Важно: агент не «знает»
проект, он видит только то, что прочитал, и делает только то, что ему разрешили.

| Режим | Что делает |
|---|---|
| **Plan** | Читает, анализирует, предлагает план. Файлы не меняет. |
| **Build** | Меняет файлы и запускает команды. Здесь нужен контроль. |

---

## Правила безопасной работы

1. Сначала **Plan**, потом **Build**. В Plan агент читает, но не меняет файлы.
2. Одна задача — один файл — один понятный результат.
3. Перед запуском опасной команды читаем, что именно она делает.
4. Сломалось — `Esc`, затем `/undo`. Не «чиним» наугад.
5. Секреты, пароли и персональные данные в промпт не вставляем.
6. Любое число проверяем независимо: пересчитали руками или другим способом.

**Главная мысль:** агент — исполнитель. Ответственность за результат — на аналитике.

## Задание 2. Отчёт по статусам (22 мин)

1. Переключитесь в **Build**.
2. Вставьте промпт:

```text
Задача: добавь в tracker.py пункт меню «Отчёт по статусам».
Требования:
- использовать существующий load_tasks();
- посчитать количество задач по каждому статусу;
- печатать в формате: «в работе: 1»;
- если задач нет — «Задач нет.»;
- не менять tasks.json;
- только стандартная библиотека, Python 3.8;
- меню: 1 — показать, 2 — добавить, 3 — отчёт, 4 — выход.
Критерии приёмки:
- python3 tracker.py → пункт 3 печатает количества;
- сумма количеств равна числу задач;
- пункт 4 выходит.
Сначала покажи план изменений, потом внеси изменения.
```

3. Запустите в отдельном терминале:

```bash
python3 tracker.py
```

4. Проверьте:

- [ ] пункт 3 показывает `в работе: 1`, `готово: 1`;
- [ ] сумма равна 2;
- [ ] `tasks.json` не изменился;
- [ ] пункт 4 выходит;
- [ ] нет новых библиотек;
- [ ] нет синтаксиса Python 3.9+.

**Если агент сделал лишнее:** `Esc`, затем `/undo` или попросите «только один файл и только этот пункт меню».

## Задание 5. Отчёт `report.py` (22 мин)

1. Вставьте промпт:

```text
Создай report.py — отчёт по задачам и проверка качества данных.
Вход: путь к JSON (по умолчанию tasks.json).
Выход: сводка в консоль + report.csv.
Требования:
- только стандартная библиотека, Python 3.8;
- обязательные поля: id, задача, исполнитель, статус;
- id — целое число > 0, без дубликатов;
- задача и исполнитель — непустые строки;
- статусы привести к справочнику: новая, в работе, готово;
- «В работе», «сделано», «готова» считать вариантами написания;
- записи с ошибками не включать в сводку, но показывать в CSV;
- CSV: разделитель ';', кодировка utf-8-sig,
  колонки id, задача, исполнитель, статус, статус_норм, проблемы;
- самопроверка: сумма по статусам = число пригодных записей;
- если файла нет или JSON битый — понятное сообщение и код возврата 2;
- если есть ошибки данных — код возврата 1.
Критерии приёмки:
- materials/tasks_dirty.json: 9 записей, 5 ошибок, 3 предупреждения,
  4 пригодных, статусы 2/2;
- tasks.json: 2 записи, 0 ошибок, статусы 1/1;
- []: 0 записей, код 0;
- нет файла: код 2.
```

2. Проверьте по чек-листу. Не нужно читать каждую строку кода:
   проверяйте поведение, числа и граничные случаи.

- [ ] грязные данные: 9 записей, 5 ошибок, 3 предупреждения, 4 пригодных;
- [ ] сумма по статусам равна 4;
- [ ] чистые данные: 2 записи, 0 ошибок, статусы 1/1;
- [ ] `[]`: 0 записей, код 0;
- [ ] нет файла: понятное сообщение, код 2;
- [ ] битый JSON: без трейсбека;
- [ ] CSV открывается в Excel/LibreOffice без «кракозябр»;
- [ ] только стандартная библиотека;
- [ ] Python 3.8.

3. Проверка кода возврата:

```bash
python3 report.py materials/tasks_dirty.json
echo $?
```

Windows:

```bat
python report.py materials\tasks_dirty.json
echo %ERRORLEVEL%
```

**Важно:** оценивается не красота кода, а сходимость результата и проверка.
