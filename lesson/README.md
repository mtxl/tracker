# Комплект занятия: агенты в OpenCode для аналитика

Готовые материалы для двух пар по 90 минут на базе проекта `tracker`.
Группа — ИТ ОРСИ, профиль «аналитика», слабая подготовка.
Код — только стандартная библиотека Python, совместимость с Python 3.8.

## Что внутри

| Файл | Для кого | Зачем |
|---|---|---|
| `plan.md` | преподаватель | Полный сценарий: хронокарта, промпты, ожидаемые ответы, риски |
| `handout.md` | студенты | Раздатка с заданиями, чек-листами и домашкой |
| `materials/AGENTS.md` | студенты | Образец правил проекта |
| `materials/analyst.md` | студенты | Образец подагента-аналитика |
| `materials/tasks_dirty.json` | студенты | Данные с намеренными проблемами качества |
| `materials/opencode.json` | преподаватель | Пример разрешений для демонстрации безопасности |
| `solutions/report.py` | преподаватель | Эталонный отчёт и проверка данных |
| `solutions/sample_audit.md` | преподаватель | Пример ответа агента для сверки или офлайн-варианта |

`solutions/report.py` — **не показывать до практики 4**: студенты должны
сначала получить свой результат и проверить его, а не копировать эталон.

## Быстрый старт

1. Проверьте окружение:

   ```bash
   opencode --version   # нужен 2.x
   python3 --version    # нужен 3.8+
   cd tracker
   python3 tracker.py
   ```

2. Скопируйте проект для каждой пары или работайте в одном репозитории.

3. Разложите материалы:

   ```bash
   cp lesson/materials/AGENTS.md ./AGENTS.md
   mkdir -p .opencode/agents
   cp lesson/materials/analyst.md .opencode/agents/analyst.md
   ```

   `opencode.json` копируйте только в песочницу для демонстрации разрешений:
   он меняет поведение агента и не нужен для остальных заданий.

4. Распечатайте `handout.md`.

5. Откройте `plan.md` и ведите по хронокарте.

## Логика занятия

**Пара 1 — управление агентом.**

- чат vs агент;
- Plan mode: аудит без изменений;
- Build mode: одна маленькая правка;
- `AGENTS.md`: постоянные правила проекта;
- рефлексия.

**Пара 2 — агент под задачу аналитика.**

- постановка задачи: контекст, ограничения, критерии, проверка;
- свой подагент `analyst` с запретом на изменения;
- аудит грязных данных;
- `report.py` со сводкой, CSV и проверкой качества;
- разрешения и риски;
- итоги.

## Если пар меньше или больше

- **Если занятия по 45 минут:** оставьте практику 1, практику 2 и рефлексию;
  практику 3 и 4 перенесите на следующее занятие.
- **3 пары:** добавьте отдельную пару на тесты, `--strict` и группировку
  по исполнителям.
- **Нет сети/токенов:** проведите демонстрацию на своём ноутбуке, раздайте
  распечатку ответа агента, оставьте проверку и обсуждение.

## Проверка эталона

```bash
cd lesson
python3 solutions/report.py materials/tasks_dirty.json
```

Ожидается: 9 записей, 5 ошибок, 3 предупреждения, 4 пригодных записи,
статусы `в работе` — 2 и `готово` — 2, код возврата 1.

```bash
python3 solutions/report.py ../tasks.json
```

Ожидается: 2 записи, 0 ошибок, статусы 1/1, код возврата 0.

## Важные мелочи

- `tracker.py` использует `input()`, поэтому запускайте его в отдельном
  терминале, а не внутри TUI OpenCode.
- Для автоматического прогона меню: `printf '3\n4\n' | python3 tracker.py`.
- На Windows: `python` вместо `python3`, `echo %ERRORLEVEL%` вместо `echo $?`.
- После экспериментов откат: `git checkout -- tracker.py tasks.json`.
- OpenCode 2.x подхватывает изменения `.opencode/agents/*.md` и `AGENTS.md`
  без перезапуска.
